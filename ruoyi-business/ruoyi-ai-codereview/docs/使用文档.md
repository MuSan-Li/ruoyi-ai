# ruoyi-ai-codereview 使用文档

## 一、模块概述

`ruoyi-ai-codereview` 是 RuoYi-AI 平台的 **AI 代码审查模块**，通过对接 Git 平台（GitLab/GitHub/Gitea）的 Webhook，自动对代码变更进行 AI 审查，并将审查结果回写到 MR/PR 评论中，同时支持多渠道通知推送。

### 核心特性

| 特性 | 说明 |
|------|------|
| **多平台支持** | GitLab、GitHub、Gitea |
| **事件类型** | Merge Request、Pull Request、Push |
| **AI 审查** | 基于框架模型管理，调用 LLM 进行代码审查 |
| **多维度评分** | 功能性、安全性、最佳实践、性能、Commit规范（满分100） |
| **评论回写** | 自动将审查结果作为评论发布到 MR/PR/Commit |
| **通知推送** | 钉钉、企业微信、飞书、自定义 Webhook |
| **审查记录** | 持久化存储，支持统计分析 |
| **可配置风格** | 专业严谨、幽默讽刺、温和友善、轻松幽默 |

## 二、安装步骤

### 1. 执行 SQL 脚本

在 MySQL 数据库中执行以下脚本：

```bash
source ruoyi-business/ruoyi-ai-codereview/src/main/resources/sql/codereview.sql
```

或手动执行：

### 2. 配置 application.yml

在 `ruoyi-admin` 的配置文件中添加以下配置：

```yaml
# AI 代码审查配置
codereview:
  enabled: true

  # LLM 配置 - 使用框架模型管理中配置的模型
  llm:
    model-name: deepseek-chat  # 模型名称，需在模型管理中预先配置

  # 平台配置
  platform:
    gitlab:
      enabled: true
      url: https://gitlab.example.com  # GitLab 服务器地址
      token: ${GITLAB_TOKEN}           # Personal Access Token
      webhook-secret: your-secret      # Webhook 密钥（可选）
    github:
      enabled: true
      url: https://api.github.com      # GitHub API 地址
      token: ${GITHUB_TOKEN}           # Personal Access Token
      webhook-secret: your-secret      # Webhook 密钥（可选）
    gitea:
      enabled: true
      url: https://gitea.example.com   # Gitea 服务器地址
      token: ${GITEA_TOKEN}            # Personal Access Token
      webhook-secret: your-secret      # Webhook 密钥（可选）

  # 通知配置
  notify:
    dingtalk:
      enabled: false
      webhook-url: https://oapi.dingtalk.com/robot/send?access_token=xxx
      secret-enabled: false
      secret: your-secret
    wecom:
      enabled: false
      webhook-url: https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx
    feishu:
      enabled: false
      webhook-url: https://open.feishu.cn/open-apis/bot/v2/hook/xxx
    extra-webhook-url: https://your-server.com/callback

  # 审查配置
  review:
    # 审查的文件扩展名
    extensions: .c,.cc,.cpp,.cs,.css,.cxx,.go,.h,.hh,.hpp,.hxx,.java,.js,.jsx,.md,.php,.py,.sql,.ts,.tsx,.vue,.yml
    # 最大 Token 数（超出会截断）
    max-tokens: 10000
    # 审查风格：professional(专业) / sarcastic(讽刺) / gentle(温和) / humorous(幽默)
    style: professional
    # 是否启用 Push 审查
    push-enabled: true
    # 是否只审查受保护分支的 MR
    merge-review-only-protected-branches: false
```

### 3. 配置模型

在 **模型管理** 中添加用于代码审查的模型：

- 模型名称：`deepseek-chat`（与配置中的 `model-name` 一致）
- 供应商：根据实际选择（如 DeepSeek、OpenAI 等）
- API Key：填写对应供应商的 API Key

## 三、Git 平台 Webhook 配置

### GitLab 配置

1. 进入项目 → **Settings** → **Webhooks**
2. 填写配置：

| 配置项 | 值 |
|--------|-----|
| **URL** | `http://your-server/codereview/webhook/gitlab` |
| **Secret Token** | 配置文件中的 `webhook-secret` |
| **Trigger** |勾选 `Merge Request events` 和 `Push events` |

3. 点击 **Add webhook** 保存

### GitHub 配置

1. 进入仓库 → **Settings** → **Webhooks** → **Add webhook**
2. 填写配置：

| 配置项 | 值 |
|--------|-----|
| **Payload URL** | `http://your-server/codereview/webhook/github` |
| **Secret** | 配置文件中的 `webhook-secret` |
| **Content type** | `application/json` |
| **Events** | 选择 `Pull requests` 和 `Pushes` |

3. 点击 **Add webhook** 保存

### Gitea 配置

1. 进入仓库 → **Settings** → **Webhooks** → **Add Webhook** → **Gitea**
2. 填写配置：

| 配置项 | 值 |
|--------|-----|
| **Target URL** | `http://your-server/codereview/webhook/gitea` |
| **Authorization Header** | 配置文件中的 `webhook-secret` |
| **Trigger On** | 选择 `Push events` 和 `Pull Request events` |

3. 点击 **Add Webhook** 保存

```
           ┌─────────────┐             ┌─────────────┐             ┌─────────────┐
           │ 获取代码变更 │             │  AI 审查    │             │ 保存日志    │
           │ (Git API)   │             │  (LLM)      │             │ (MySQL)     │
           └─────────────┘             └─────────────┘             └─────────────┘
                    │                           │
                    │                           ▼
                    │                   ┌─────────────┐

                    │                           │
                    ▼                           ▼
           ┌─────────────┐             ┌─────────────┐
           │ 发送通知    │◀────────────│ 钉钉/企微   │
           │ (Notifier)  │             │ 飞书/Webhook│
```

### 审查评分维度

| 维度 | 分值 | 说明 |
|------|------|------|
| 功能性 & 健壮性 | 40分 | 逻辑正确性、边界条件、异常处理 |
| 安全 & 险 | 30分 | SQL注入、XSS、越权、敏感信息泄露 |
| 最佳实践 | 20分 | 代码风格、设计模式、可维护性、命名规范 |
| 性能 & 效率 | 5分 | 性能问题、资源泄漏 |
| Commit Message | 5分 | 提交信息是否清晰描述变更内容 |

## 五、API 接口

### Webhook 接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/codereview/webhook/gitlab` | POST | 接收 GitLab Webhook |
| `/codereview/webhook/github` | POST | 接收 GitHub Webhook |
| `/codereview/webhook/gitea` | POST | 接收 Gitea Webhook |

### 管理接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/admin/codereview/config` | GET | 获取当前配置 |
| `/admin/codereview/config/llm` | PUT | 更新 LLM 配置 |
| `/admin/codereview/config/platform` | PUT | 更新平台配置 |
| `/admin/codereview/config/notify` | PUT | 更新通知配置 |
| `/admin/codereview/config/review` | PUT | 更新审查配置 |

| `/admin/codereview/log/push/list` | GET | Push 审查记录列表 |

### 接口示例

```bash
# 获取 MR 审查记录
curl "http://your-server/admin/codereview/log/mr/list?pageNum=1&pageSize=10"

# 获取统计数据
curl "http://your-server/admin/codereview/log/statistics?startDate=2024-01-01&endDate=2024-12-31"

  -H "Content-Type: application/json" \
```

## 六、审查风格说明

| 风格 | 值 | 特点 |
|------|-----|------|
| **专业严谨** | `professional` | 默认风格，直接指出问题并提供解决方案 |

## 七、常见问题

### Q1: Webhook 收到请求但没有执行审查？

检查以下配置：
- `codereview.enabled` 是否为 `true`
- 对应平台 `platform.gitlab.enabled` 等是否为 `true`
- 模型名称是否在模型管理中正确配置

### Q2: AI 审查失败？

检查以下项：
- 模型是否在模型管理中配置且启用
- API Key 是否有效
- 模型供应商是否正常服务

### Q3: 评论没有回写到 Git 平台？

检查以下项：
- 平台 Token 是否有写入评论的权限
- Git 平台 API 地址是否正确
- 查看 logs 目录下的日志文件

### Q4: Draft MR 为什么没有审查？

模块默认跳过 Draft/WIP状态的 MR/PR，这是设计行为。

### Q5: 如何只审查 main/master 分支的 MR？

设置配置：
```yaml
codereview:
  review:
    merge-review-only-protected-branches: true
```

## 八、注意事项

1. **Token 权限**：Git 平台的 Token 需要有 `api` 或 `repo` 权限才能发表评论
2. **异步处理**：审查过程是异步执行的，不会阻塞 Webhook 响应
3. **重复审查**：相同 `last_commit_id` 的 MR 不会重复审查
4. **Token 限制**：超出 `max-tokens` 的代码变更会自动截断
5. **文件过滤**：只审查配置中 `extensions` 指定的文件类型
6. **删除操作**：`delete` 类型的变更不会审查
